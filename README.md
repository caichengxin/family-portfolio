# Family Portfolio V1.3B - Members Management

Prerequisites: deployed 01/02 SQL, 03 market-quotes Edge Function, and V1.3A. Before uploading the eight root files to GitHub Pages, apply the separate `Family_Portfolio_04_Members.sql` in Supabase SQL Editor. Confirm both functions deny anon and grant authenticated execution with pinned search paths. Run `Family_Portfolio_04_Security_Test.sql` separately in SQL Editor as postgres using the two existing test users in different groups. The successful test ends with ROLLBACK then a PASS row; any failed assertion must be investigated before using real financial data. The security test intentionally impersonates authenticated identities inside a transaction; it must never be exposed via the application.

- Super Admin sees a Members directory, including inactive memberships. Link a confirmed Auth user already created in Supabase by UID; choose group and Member or Group Admin. No public registration, no invitation emails, and no passwords or secrets in browser code.
- Manage non-super-admin memberships: display name, group, role and active status. The two new security-definer RPCs enforce caller authorization, same-family group validation, and protected super-admin roles. They cannot enable another user's financial sharing. Changing households, disabling or re-enabling a previously disabled user clears consent; financial records are retained. An inactive member cannot access family data on the next server request. Previously viewed data cannot be remotely erased from a user's device.
- Members control sharing in Settings. Group Admin can view authorized data in their own group but cannot manage memberships. Keep public and anonymous sign-ups disabled.
- Personal Alpaca IEX quote behavior is unchanged from V1.3A: only the original administrator's own account uses session-memory quotes. No quote redistribution, shared price cache, daily snapshots, or background market updates. Confirm provider permission before family-wide quotes.
- Member invitation emails, password setup/recovery, push, buy plans, membership change audit history, deletion of test data, and full production security review are not part of this release. Test data only until security checks pass.

Validation: JS syntax and local browser UI tests with mock backend passed (member list, role gating, link/update RPC arguments, mobile width). SQL was inspected against 01/02 migrations; no PostgreSQL instance or live credentials were used to run it here. Actual Supabase execution and permission testing remain required.
